# Архитектура VSM

Консольное bash-меню для VPS. Ставит и обслуживает VPN/прокси-стек. Запускается
из `~/.bashrc` при каждом входе по SSH.

## Слои

В корне репозитория лежат ровно три файла: `vsm`, `install.sh`, `uninstall.sh`.
Всё остальное разложено по каталогам, и в `/usr/local/bin` уходит **одна**
ссылка — `vsm`. Меню и установщики находят друг друга по своему расположению
через `VSM_ROOT`, который задаёт `lib/common.sh`.

```
vsm ─────────────────────► главное меню (статусы, адреса, диспетчер)
 │
 ├─ menus/xui.sh ────────► панель 3x-ui-pro
 ├─ menus/telemt.sh ─────► стек telemt: маска, панель, MTProxyL
 ├─ menus/awg.sh ────────► AmneziaWG 2.0/3.0 (контейнер, свой UDP-порт)
 ├─ menus/bots.sh ───────► Telegram-боты (4 режима)
 ├─ menus/tests.sh ──────► проверки сети и производительности
 ├─ menus/setup.sh ──────► BBR, ICMP, UFW, IPv6, TZ, SSL, WARP
 ├─ menus/utils.sh ──────► htop, ncdu, порты, очистка
 └─ menus/warp.sh ───────► Cloudflare WARP (вызывается из setup)

общий слой (source из всех меню — одной строкой lib/common.sh):
 lib/common.sh   точка подключения; задаёт VSM_ROOT и VSM_LIB
 lib/ui.sh       палитра и примитивы вывода (ui_item, ui_pad, ui_title…)
 lib/config.sh   статусы служб, IPv6 из ядра, адреса панелей, учётки
 lib/deps.sh     apt, установка пакетов, отпечатки чужих установщиков
 lib/nginx_mask.sh        генератор self-SNI vhost
 lib/nginx_panel_proxy.sh доступ к telemt_panel через 443

установщики (самодостаточные, НЕ подключают общий слой):
 stacks/telemt.sh           стек telemt, режимы full | addon
 stacks/awg.sh              AmneziaWG, режимы install | uninstall | dedupe
 stacks/bots.sh             боты
 stacks/nginx-openssl35.sh  пересборка nginx с OpenSSL 3.5 (PQ TLS)

прочее:
 tools/awg2mihomo.sh  конвертер клиентского конфига AWG в формат clash-meta
 checks/ui.sh         статика оформления (~4 с), гоняется перед коммитом
 checks/accept.sh     приёмка: запускает меню на живом сервере
 bots/                исходники Telegram-ботов
```

Почему `lib/` не получает бит исполнения: эти файлы сорсятся, а не
запускаются. Почему `checks/` не попадает в `/usr/local/bin`: это инструмент
разработчика, на боевом сервере ему в PATH делать нечего.

## Self-SNI маскировка — суть системы

```
клиент Telegram ─► telemt :8444 ─► MTProto
случайный сканер ─► telemt :8444 ─► сплайсинг ─► nginx 127.0.0.1:7444
                                                  └─► тот же сертификат,
                                                      тот же webroot,
                                                      что у панели на 443
```

Критерий целости — **не** «служба active», а совпадение отпечатка сертификата,
ALPN, шифра и группы обмена между 7444 и 443. Проверяется пунктом
«Сверить TLS маски и панели» (`check_tls_parity` в `menus/telemt.sh`).

## Маршрутизация 443

```
:443 ─► nginx stream, разбор SNI (ssl_preread)
        ├─ $DOMAIN_PANEL   ─► :7443 (proxy_protocol) ─► vhost панели
        │                        ├─ /<webBasePath>/panel/  панель 3x-ui
        │                        └─ /<PANEL_PREFIX>/       telemt_panel
        └─ $DOMAIN_REALITY ─► REALITY / Xray
```

Имена доменов берутся из `/etc/vsm/telemt.conf`. В документации они намеренно
не указываются: репозиторий публичный, а связка «домен ↔ назначение сервера» —
ровно то, что вся маскировка и старается не выдавать.

Нужны **два разных** поддомена: `stream map` строит ключи по SNI, одинаковые
значения дают `conflicting parameter`.

## Инварианты

| № | Правило | Почему |
|---|---|---|
| 1 | Маска в `/etc/nginx/conf.d/`, не в `sites-enabled` | установщик и патч 3x-ui-pro вычищают `sites-enabled` целиком |
| 2 | `telemt.service` имеет `Requires=nginx.service` | остановка nginx уносит telemt; любой останов обязан иметь парный подъём |
| 3 | Маска ≡ панель по TLS | расхождение — признак для активного пробера |
| 4 | Секрет MTProto и пароль панели переиспользуются | перегенерация ломает выданные клиентам ссылки |
| 5 | Разрушающие операции — ввод слова целиком | `СТЕРЕТЬ` / `УДАЛИТЬ`, регистр учитывается |
| 6 | В главном меню нет секретов | открывается при каждом входе, скриншот в публичном README |
| 7 | `nginx reload` возвращается раньше слушателя | нужен `wait_until`, не `sleep` |
| 8 | Объединённый и отдельные боты взаимоисключающие | два процесса на один токен дают 409 Conflict |

## Целевое состояние сервера

Пять активных служб: `nginx`, `x-ui`, `telemt`, `telemt-panel`, и один из
`3xui-telemt-bot` | `telemt-bot` + `3xui-monitor`.

## AmneziaWG — рядом, но не в стеке

```
клиент AmneziaVPN ─► <порт AWG>/udp ─► amneziawg-go (контейнер, host-режим)
                                        └─► NAT наружу; DNS 1.1.1.1 внутри туннеля
```

Один контейнер, без своего резолвера: тот жил на docker-мосту и из туннеля
недостижим — Docker 29 запрещает доступ к адресам контейнеров в таблице `raw`.
`AllowedIPs` у клиентов — `0.0.0.0/0, ::/0`; `::/0` здесь заглушка, адреса IPv6
у туннеля нет, и трафик v6 гибнет в нём вместо утечки мимо VPN.

Пересечений со стеком нет: nginx, сертификаты и порты панели не трогаются,
занимается только один UDP-порт. Ставится и снимается независимо.

**Host-режим обязателен.** При публикации порта через `-p` Docker вставляет
свои правила и обходит UFW: измерено на стенде — пакет доходит до контейнера,
когда UFW активен и правила для порта нет. Меню показывало бы порт закрытым,
пока он открыт.

**Форвардинг — персистентно.** Без записи в `/etc/sysctl.d/` после
перезагрузки `ip_forward=0`: контейнеры подняты, порт слушает, узел выглядит
исправным, а трафик клиентов маршрутизировать нечем.

## Оформление меню

Собрано из примитивов в `lib/common.sh`, а не из литералов в каждом
файле: `ui_title`, `ui_section`, `ui_item`, `ui_danger_item`, `ui_kv`,
`ui_secret`, `ui_pad`, `ui_cols`, `ui_narrow`.

| Роль | Что означает |
|---|---|
| `C_NAME` | имя пункта, функции, параметра — синий |
| `C_DESC` | описание и значение — серый |
| `C_KEY` | клавиша выбора |
| `C_OK` / `C_WARN` / `C_DANGER` | состояние: цвет здесь несёт смысл, а не роль |
| `C_SECRET` | учётные данные — **жирным, не цветом** |

Три правила, каждое написано кровью и стережётся `checks/ui.sh`:

1. **Эмодзи с вариационным селектором (`U+FE0F`) запрещены** — рендерятся в
   одну или две ячейки в зависимости от терминала. В исходном меню их было 77
   строк, и автор компенсировал съезд лишним пробелом под свой терминал.
2. **Цвет только из палитры.** Вписанные байтами escape-коды проходят мимо
   `NO_COLOR` и мимо снятия цвета без терминала.
3. **Подпись обязана быть короче своей колонки**, а не равной ей: `ui_pad`
   дополняет только то, что короче, и при равенстве значение печатается
   вплотную — `Виртуализацияkvm`.

Значок в выравнивание не входит: его ширина в ячейках зависит от терминала, и
посчитать её нечем. Колонки отсчитываются от подписи — съехать может сам
значок, но не таблица за ним, при условии что значок на строке ровно один.

Ширина берётся из `VSM_COLS`, затем `tput cols`, затем `COLUMNS`, иначе 80.
Переопределение нужно для проверок: при выводе в пайп `tput` отвечает не
шириной окна, а значением из terminfo, и проверка узкого экрана молча проходит
на восьмидесяти колонках.

## Самонаблюдение

Слой, который следит не за прокси, а за самим VSM. Появился после аудита
эксплуатации: почти все механизмы проекта существуют, чтобы поймать тихий
отказ, — и до этого слоя тихий отказ был возможен в них самих.

```
┌─ сторож telemt (внутри бота) ──────────────────────┐
│  опрашивает движок, шлёт тревоги, рисует карточку  │
│  раз в минуту отмечается в watchdog.heartbeat      │
└────────────────────┬───────────────────────────────┘
                     │  а кто следит за ним?
┌────────────────────▼───────────────────────────────┐
│  vsm-heartbeat.timer — раз в 5 минут, НЕ зависит   │
│  от бота, шлёт в Telegram сам через curl           │
│  tools/heartbeat-check.sh                          │
└────────────────────────────────────────────────────┘
```

**Почему отдельным таймером.** Уведомлять о смерти бота силами этого же бота
нельзя. Проверяются три способа замолчать незаметно, каждый из которых
`systemctl is-active` не ловит:

| Способ | Чем виден |
|---|---|
| Служба остановлена | состоянием службы |
| Петля перезапусков | ПРИРОСТОМ счётчика `NRestarts` за интервал |
| Зависшая корутина | возрастом отметки `watchdog.heartbeat` |

Петля перезапусков обрывается на пятом падении подряд
(`StartLimitIntervalSec=300`): молчащий бот, который числится живым, опаснее
остановленного — о втором расскажет наблюдатель.

## Реестр решений и сверка

VSM не владеет ни одним из компонентов, которыми управляет. Его ценность —
не скрипты, а **решения**: осознанные отступления от чужих умолчаний ради
незаметности. Проблема в том, что решения нигде не записаны как решения, и
любое чужое обновление накатывает умолчания обратно.

[`lib/expectations.sh`](../../lib/expectations.sh) объявляет их списком,
[`checks/drift.sh`](../../checks/drift.sh) сверяет с действительностью.

Два класса, и разница между ними — цена ошибки:

- **`fix`** — незаметность и безопасность. Чинится молча, о починке
  сообщается постфактум: цена бездействия выше цены неожиданности.
- **`tell`** — всё остальное. Показывается и ждёт человека.

Общесистемные настройки (журналирование, права sudoers, чужие таймеры) —
всегда `tell`. Молча возвращать их значило бы вести себя ровно так, как ведут
себя чужие обновления, за которыми реестр и следит.

Позиции, у которых «ожидание» — не константа, а запомненная база сравнения
(чужие таймеры, права sudoers, включённая владельцем настройка
журналирования), хранят её в `/etc/vsm/expectations.state`. Признаком служит
**запомненное решение**, а не наличие файла: иначе снесённая настройка
выглядела бы как «вы её и не включали».

Отключить любую позицию — её id строкой в `/etc/vsm/expectations.local`.

## Обслуживание

| Инструмент | Что делает | Когда |
|---|---|---|
| [`tools/vsm-backup.sh`](../../tools/vsm-backup.sh) | Копия невоспроизводимого: секрет прокси, префиксы, учётки панелей, токены | `vsm-backup.timer`, раз в сутки |
| [`tools/heartbeat-check.sh`](../../tools/heartbeat-check.sh) | Жив ли бот | `vsm-heartbeat.timer`, раз в 5 минут |
| [`tools/disk-cleanup.sh`](../../tools/disk-cleanup.sh) | Отчёт о месте, уборка, устранение причины роста логов | Вручную: «Утилиты» → «Очистка» |
| [`lib/panels.sh`](../../lib/panels.sh) | Одна веб-панель на сервер | Перед установкой любой из них |

Резервная копия лежит **на том же диске**: она защищает от случайного
удаления и неудачной правки, но не от гибели диска. Против этого помогает
только вынос архива наружу, и скрипт печатает готовую команду при каждом
запуске.
