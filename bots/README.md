# Telegram-боты

Три точки входа на **одном** наборе кода. Устанавливаются пунктом **3** в `vsm`.

| Точка входа | Служба | Что делает |
|---|---|---|
| [`run_combined.py`](run_combined.py) | `3xui-telemt-bot` | Обе функции в одном боте: разделы переключаются кнопками, есть общая сводка |
| [`run_telemt.py`](run_telemt.py) | `telemt-bot` | Только мониторинг панели Telemt |
| [`run_xui.py`](run_xui.py) | `3xui-monitor` | Только панели 3x-ui |

Объединённый и отдельные боты **взаимоисключающие**: иначе два процесса дублировали бы сбор IP и опрос панелей. Установщик снимает лишние службы сам.

## Структура

```
config.py       единые настройки всех точек входа, читает .env
common/         auth.py (доступ), keyboards.py, menu.py (корень), runner.py (запуск)
telemt/         пакет: app.py, api/, handlers/, utils/, keyboards/, scripts/
xui/            пакет: app.py, api.py, database.py
data/           базы и GeoIP — общие, вне git
venv/           общее окружение, вне git
```

Раньше боты жили в отдельных каталогах со своими `config.py` и `api`. Сложить их в один процесс было нельзя: `import config` разрешался в тот, что оказался первым в `sys.path`. Поэтому код упакован в `telemt/` и `xui/`, а настройки сведены в один `config.py`.

## Клавиатура объединённого бота

Telegram показывает ровно одну reply-клавиатуру на чат, а кнопок у двух ботов вместе набирается полтора десятка и число растёт с каждой панелью. Поэтому клавиатура многоуровневая:

```
корень                      раздел 3x-ui                управление панелями
[ ✈️ Telemt ] [ 🎛 3x-ui ]  [ 📊 Общий статус        ]  [ ➕ Добавить ] [ 🗑️ Удалить ]
[      ℹ️ Сводка         ]  [ 📱 панель ] [ 📱 ... ]    [ ✏️ Изменить дату         ]
                            [ 🛠 Управление панелями ]  [ ◀️ К панелям             ]
                            [ ⬅️ Назад               ]
```

Выбор раздела заменяет клавиатуру на кнопки соответствующего бота плюс `⬅️ Назад`. Подписи совпадают с подписями отдельных ботов, поэтому обработчики обслуживают оба режима без изменений.

Редкие операции над панелями убраны на третий уровень, чтобы не занимать строку в разделе. У подменю **своя** кнопка возврата `◀️ К панелям`: общий `⬅️ Назад` означает «в корень» и обработан только в объединённом боте, а подъём на один уровень нужен одинаково в обоих режимах.

`ℹ️ Сводка` — общий статус панелей 3x-ui и статистика Telemt одним нажатием. Части отправляются независимо: если одна подсистема недоступна, вторая всё равно покажется.

### Пошаговый диалог и кнопки

Добавление панели и правка её срока — это FSM, где обработчик ловит любой текст. Нажатие кнопки меню посреди диалога иначе уехало бы в имя или токен панели. Поэтому:

- кнопочные обработчики объявлены с `StateFilter(None)` — в диалоге они не срабатывают;
- в диалоге показывается клавиатура с единственной кнопкой `❌ Отмена`;
- нажатие любой другой кнопки меню перехватывается и подсказывает завершить ввод или отменить;
- любая новая reply-кнопка обязана попасть в `MENU_BUTTONS`, иначе этот перехват её не увидит.

### Выбор даты

`common/datepicker.py` — общий виджет для обоих сценариев: пресеты, инлайн-календарь на stdlib `calendar` и ручной ввод. Наружу дата всегда `ДД-ММ-ГГГГ`, в базу уходит ISO — так её читают фоновые алерты о сроке и таблица общего статуса, и менять их ради формата ввода незачем.

Имя панели в кнопках виджета не передаётся: в `callback_data` всего 64 байта, а кириллическое имя тратит по два байта на символ. Панель хранится в состоянии, в кнопках — только координаты даты. По той же причине `process_name` ограничивает имя 48 байтами: оно уезжает в `callback_data` кнопок удаления и правки, и слишком длинное сломало бы всю инлайн-клавиатуру целиком.

Пустые ячейки сетки календаря идут через свою `CallbackData`, а не через строку `"noop"`: такой обработчик уже есть в telemt-части, а её роутеры подключаются раньше 3x-ui.

## Данные

Всё в `data/`, общее для всех трёх точек входа — переключение режима не теряет ни историю, ни список панелей:

- `ip_history.db` — пары «пользователь ↔ IP», собираются раз в `COLLECT_INTERVAL_MINUTES`
- `bot_monitor.db` — панели 3x-ui: адрес и **токен доступа**
- `geoip/` — базы MaxMind GeoLite2 (~175 МБ), обновляются `telemt/scripts/update_geoip.sh`

Карта пишется в `/var/www/telemt-map/map.html` — не в репозиторий: у `/root` права `drwx------`, и nginx под `www-data` туда не попадёт.

## Настройка

Один файл `.env` на все точки входа, создаётся установщиком с правами `600`. Образец — [`.env.example`](.env.example). Нужен только тот токен, который соответствует выбранному режиму.

Доступ — общий список `ADMIN_IDS`. Посторонние игнорируются молча: ответ вроде «нет доступа» подтверждал бы, что бот существует.

## Ручная установка

```bash
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
cp .env.example .env   # заполнить токен и ADMIN_IDS
./telemt/scripts/update_geoip.sh
./venv/bin/python run_combined.py
```

Внешние зависимости для telemt-части: API панели на `TELEMT_API_URL`, Prometheus на `PROMETHEUS_METRICS_URL` и `/etc/telemt/telemt.toml` для `/status`.
