# Безопасность

## Что здесь считается уязвимостью

VSM управляет прокси, задача которых — оставаться незаметными. Поэтому к
обычному списку («выполнение кода», «повышение прав», «утечка секретов»)
добавляется ещё один класс, специфичный для этого проекта:

**Всё, что делает сервер отличимым от обычного сайта, — уязвимость.**

Примеры настоящих находок из истории проекта:

- панель администратора слушала отдельный порт с собственным сертификатом:
  одного соединения хватало, чтобы классифицировать сервер;
- страница карты подключений отдавала свой секретный путь четырём CDN через
  заголовок `Referer`;
- один и тот же адрес отвечал по-разному на 443 и на порту прокси — готовый
  однозапросный признак проксирования.

Отдельно: **отказ, о котором не сообщили, тоже уязвимость.** Механизм, который
рапортует об успехе поверх сломанной системы, опаснее отсутствующего, потому
что создаёт ложную уверенность.

## Как сообщить

Пользуйтесь приватным каналом GitHub: вкладка **Security → Report a
vulnerability**. Он виден только сопровождающему.

**Не открывайте публичный issue** до того, как исправление вышло: описание
признака, по которому сервер отличим, — это готовая инструкция для того, от
кого прячутся пользователи.

## Чего НЕ присылать

Отчёт не должен содержать данных вашей установки. Их не нужно ни нам, ни тем,
кто прочитает отчёт после раскрытия:

| Не присылать | Почему |
|---|---|
| Домен FakeTLS и домен панели | Публикация адреса живого прокси — сама по себе его компрометация |
| `TELEMT_SECRET`, токены ботов, пароли панелей | Дают полный доступ |
| Секретные префиксы путей (`PANEL_PREFIX`, путь карты) | Единственная защита этих страниц |
| Внешний IP сервера | Достаточно сказать «сервер за NAT» / «прямой IP» |
| Журналы целиком | В них попадают адреса пользователей прокси |

Замените всё это заглушками: `panel.example.com`, `<СЕКРЕТ>`, `203.0.113.10`
(диапазон RFC 5737 для документации).

## Что входит в область ответственности

**Входит:** код этого репозитория — меню, установщики, библиотеки, боты,
проверки.

**Не входит:** сторонние компоненты, которые VSM устанавливает, — telemt,
3x-ui-pro, MTProxyL, AmneziaWG и их панели. О дефектах в них сообщайте их
авторам. Но если **VSM настраивает их небезопасно** — это наша уязвимость, и
мы её ждём.

VSM намеренно не фиксирует версии сторонних компонентов: это отрезало бы и
исправления безопасности. Вместо этого он запоминает отпечатки чужих
установщиков и громко сообщает, когда файл изменился (`lib/deps.sh`), а
изменения в их настройках ловит сверка с реестром решений
(`checks/drift.sh`).

## Что делать, если секрет уже утёк

1. **Токен бота** — `/revoke` у [@BotFather](https://t.me/BotFather), затем
   новый токен в `bots/.env` и `systemctl restart` службы бота.
2. **`TELEMT_SECRET`** — смена оборвёт подключение у всех клиентов разом:
   ссылки придётся выдать заново. Резервная копия секретов лежит в
   `/var/backups/vsm/config/` (`tools/vsm-backup.sh`).
3. **Секретный префикс панели** — переприменить блок nginx пунктом меню
   «Восстановить конфигурацию nginx»; префикс сгенерируется новый.
4. **Пароль панели** — сменить в самой панели, затем обновить запомненное
   значение пунктом меню, иначе шапка будет показывать неверное.

## Поддерживаемые версии

Проект развивается в одной ветке `main`. Исправления выходят в неё; отдельных
поддерживаемых веток нет. Обновление — `bash install.sh`, он же переносит
раскладку со старых версий.
