> Текстом, а не скриншотом, намеренно: адреса панелей содержат случайный
> путь, который и есть защита от сканирования, и на картинке его пришлось бы
> замазывать вручную при каждом обновлении. Учётные данные и адреса живут в
> пункте **0**, а не на главном экране.
>
> Оформление собрано из общих примитивов в `lib/common.sh`: цвет
> задаётся ролью (синий — имя, серый — значение), учётные данные выводятся
> жирным, ширина считается от терминала, а на узком экране пары схлопываются
> в одну колонку. Сторожит это `checks/ui.sh`.
## Установка

```bash
bash <(curl -sL https://raw.githubusercontent.com/adkudryashov/VSM/main/install.sh)
```

Дальше запуск командой `vsm`. Обновление — пункт **8** в меню. Удаление:

```bash
bash <(curl -sL https://raw.githubusercontent.com/adkudryashov/VSM/main/uninstall.sh)
```

**Требования:** Ubuntu 20.04+, root, установленные `git` и `curl`. Остальное меню доставит само. Для X-UI Pro апстрим дополнительно требует Ubuntu 24.04/26.04 или Debian 12/13.

| # | Раздел | Что умеет |

| **3** | **Стек telemt / MTProto** | MTProto-прокси для Telegram, веб-панель telemt_panel, лимитер входящих соединений, современный TLS |
| **4** | **Telegram-боты** | Боты мониторинга Telemt и панелей 3x-ui — вместе или по отдельности |
| **5** | **Тестирование сервера** | Проверка доступности из РФ, замеры скорости, YABS, IPQuality, сетевые сканеры |
| **6** | **Настройка и оптимизация** | BBR, запрет ICMP, UFW, часовой пояс, SSL-сертификаты, Cloudflare WARP |
| **7** | **Системные утилиты** | htop, ncdu, nethogs, ping/mtr, активные порты, очистка системы, проверка привязки домена |
| **8** | **Обновить скрипты** | `git pull`, пересоздание ссылок и перезапуск ботов — без перезагрузки сервера |

Главный экран показывает характеристики сервера, геолокацию, статусы X-UI, telemt
и ботов, а также адреса панелей. Логинов и паролей на нём нет намеренно: меню
открывается при каждом входе по SSH, поэтому учётные данные показываются в
подменю — «Управление X-UI» для панели 3x-ui и «Стек telemt» для telemt_panel.

## Что VSM хранит на сервере

Всё, что содержит секреты, создаётся с правами `600` и принадлежит root.

| Путь | Что внутри | Права |
|---|---|---|
| `/root/VSM` | Клон репозитория; команды меню — симлинки из `/usr/local/bin` | — |
| `/etc/vsm/telemt.conf` | Домены, порты, MTProto-секрет, логин, пароль и префикс пути telemt_panel | 600 |
| `/etc/vsm/telemt-credentials.txt` | То же в читаемом виде — для пункта «Показать учётные данные» | 600 |
| `/etc/vsm/xui.conf` | Логин и пароль панели 3x-ui, введённые вручную | 600 |
| `/etc/vsm/bots.conf` | Выбранный режим Telegram-ботов | 600 |
| `/root/VSM/bots/.env` | Токены ботов и Telegram ID администраторов | 600 |
| `/etc/nginx/conf.d/telemt-mask.conf` | vhost self-SNI маскировки | — |

Пароль панели 3x-ui VSM **прочитать не может**: установщик генерирует его
случайно, показывает один раз и никуда не сохраняет, а сама панель хранит его
хэшем. Поэтому пункт «Учётные данные панели» ничего в панели не меняет — он
запоминает то, что вы уже знаете, чтобы не искать при каждом входе. Файл при
этом держит пароль открытым текстом; не нужен — сотрите его тем же пунктом.

## Порты

| Порт | Что слушает | Доступ |
|---|---|---|
| 443 | Панель 3x-ui, её сайт и telemt_panel | Извне |
| 8444 | telemt (MTProto) | Извне |
| 7444 | Цель self-SNI маскировки | Только `127.0.0.1` |
| 9444 | telemt_panel | Только `127.0.0.1` |
| 9091 | API telemt | Только `127.0.0.1` |

Порты стека меню спрашивает при установке — в таблице значения по умолчанию.

**Наружу открыты только 443 и 8444.** telemt_panel слушает loopback и отдаётся
через nginx на 443 домена панели по случайному префиксу пути — так же, как сама
3x-ui живёт по случайному `webBasePath`. Раньше она висела на 9444 с собственным
сертификатом, и снаружи это выглядело как админ-форма на нестандартном порту:
сканеру хватало одного соединения, чтобы понять назначение сервера, и работа по
маскировке порта telemt теряла смысл. Заодно панели больше не нужен доступ к
приватному ключу Let's Encrypt — TLS терминирует nginx.

Адрес панели смотрите в «Стек telemt» → «Показать учётные данные». Блок доступа
живёт в vhost панели, а его вычищает патч 3x-ui-pro — после патча прогоните
«Восстановить конфиги nginx».

## Разделы меню

Нумерация в таблицах ниже совпадает с той, что на экране.

### Управление X-UI — пункт 1

| № | Пункт | Что делает |
|---|---|---|
| 1 | Установить X-UI Pro | Панель, nginx, SSL, Clash-подписка, диагностика сети. **Стирает существующую панель** |
| 2 | Применить патч | Обновляет установку автора без изменения БД |
| 3 | AdGuard Home | DNS-over-HTTPS и блокировка рекламы на домене панели, через 443 |
| 4 | Бэкап и восстановление | Создать, показать список, вернуть из архива |
| 5 | Управление сервисом | Статус, старт, стоп, рестарт `x-ui` |
| 6 | Запустить панель X-UI | Штатное меню команды `x-ui` |
| 7 | Учётные данные панели | Показывает и записывает логин с паролем в `/etc/vsm/xui.conf`. **Пароль в панели не меняет** |
| 8 | Удалить X-UI Pro полностью | Требует ввести `УДАЛИТЬ`. Сносит панель и **вычищает nginx вместе с `/etc/nginx`** — а значит и маскировку стека telemt. Сертификаты Let's Encrypt остаются |

### Стек telemt / MTProto — пункт 3

| № | Пункт | Что делает |
|---|---|---|
| 1 | Установить весь стек с нуля | 3x-ui-pro + telemt + telemt_panel. **Стирает существующую панель**, требует ввести `СТЕРЕТЬ` |
| 2 | Добавить telemt к существующей 3x-ui-pro | Ставит только telemt и панель, базу 3x-ui не трогает |
| 3 | Статус и диагностика | Проверка служб и конфигурации, сквозной тест маскировки |
| 4 | Восстановить конфиги nginx | Пересоздаёт vhost маскировки и блок доступа к telemt_panel из сохранённых настроек — после патча панели |
| 5 | Показать учётные данные | Читает `/etc/vsm/telemt-credentials.txt`, адрес панели подставляет живой |
| 6 | Управление службами | Статус, старт, стоп, логи telemt и telemt_panel |
| 7 | MTProxyL | Ставит [лимитер, обход и тюнинг](https://github.com/Liafanx/MTProxyL): nftables, Zapret2, sysctl, фиксы для iOS. Нужен режим **Reanimator** — он применяет фиксы к уже работающему telemt, а не ставит свой. Показывает версии и выбранный режим |
| 8 | Пересборка nginx с OpenSSL 3.5 | Сборка со свежим OpenSSL, 20–40 минут |
| 9 | Удалить стек telemt | Убирает telemt и telemt_panel; 3x-ui-pro и сертификаты не трогает |

Стеку нужны два поддомена с A-записями на IP сервера — меню спросит их при установке и проверит конфигурацию само.

> **После патча или переустановки панели** прогоните «Статус и диагностика»: установщик 3x-ui-pro перезаписывает конфигурацию nginx.

> Пересборка nginx замораживает пакет (`apt-mark hold`) — security-обновления придётся ставить вручную, повторив пересборку.

### Telegram-боты — пункт 4

| Вариант | Служба | Для чего |
|---|---|---|
| **1 — Объединённый** | `3xui-telemt-bot` | Обе функции в одном чате с переключением по кнопкам и общей сводкой |
| 2 — Два отдельных бота | `telemt-bot` + `3xui-monitor` | Два токена, две службы |
| 3 — Только telemt-bot | `telemt-bot` | Только панель Telemt |
| 4 — Только 3xui-bot | `3xui-monitor` | Только панели 3x-ui |

Остальные пункты раздела: **5** — обновить код ботов с GitHub, **6** — показать текущие настройки, **7** — управление службами, **8** — удалить ботов (данные сохраняются).

**telemt-часть:** статистика панели, история подключений по IP, отчёты, метрики Prometheus, карта подключений по GeoIP.

> **Карта содержит IP всех пользователей прокси** с городом и провайдером.
> Поэтому она отдаётся по случайному адресу, который создаётся при установке и
> хранится в `/etc/vsm/bots.conf`; на домен self-SNI маскировки её повесить
> нельзя — установщик откажется. Удаление ботов снимает и файл карты, и блок из
> конфигурации nginx.
**3x-ui часть:** статусы и отчёты по панелям, добавление и удаление панелей из чата, уведомления о падении и об истечении срока VPS.

Установщик спрашивает только токен от [@BotFather](https://t.me/BotFather), Telegram ID администраторов и домен для карты. Остальное делает сам: окружение, зависимости, базы GeoIP, systemd-юниты, `location` в nginx с бэкапом и проверкой конфига.

> Объединённый и отдельные боты **взаимоисключающие** — установщик снимает лишние службы, иначе два процесса дублируют сбор данных. Данные общие, при переключении режима ничего не теряется.

> Токены и базы в репозиторий не попадают. Обновление кода — пункт **5** внутри меню ботов.

Архитектура, устройство клавиатуры и структура кода — в [bots/README.md](bots/README.md).

## Разрушающие операции

Всё, что нельзя откатить, подтверждается **вводом слова целиком**, а не нажатием `y`. Регистр учитывается.

| Операция | Слово | Что переживает удаление |
|---|---|---|
| Установка стека с нуля | `СТЕРЕТЬ` | — панель ставится заново |
| Удалить X-UI Pro полностью | `УДАЛИТЬ` | Сертификаты Let's Encrypt. **Не переживает** маскировка telemt: `/etc/nginx` сносится целиком |
| Удалить стек telemt | `УДАЛИТЬ` | 3x-ui-pro, сертификаты; конфиг и учётные данные — по отдельному вопросу |
| Удалить ботов | `УДАЛИТЬ` | Данные в `bots/data`: история IP, список панелей, базы GeoIP |
| Обновить код ботов при своих правках в `bots/` | `СТЕРЕТЬ` | Спрашивается, только если правки есть; иначе обновление идёт молча |
